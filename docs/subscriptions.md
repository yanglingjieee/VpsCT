# 用户的链接、线路和规则

[返回 README](../README.md) · [网络与中转](network.md) · [隐私说明](privacy.md)

## 1. 一个链接

每个用户只有一个链接（`/r/<码>`，或较长的 `/s/<令牌>`）：

- 浏览器打开是他自己的页面：用量、线路、一键导入的按钮。
- 客户端打开是配置。面板按客户端给出它读得懂的那一种：

| 客户端 | 得到什么 |
|---|---|
| Clash 类（Clash Verge、FlClash、Clash Meta、Stash、mihomo） | Clash 配置：线路、一个选线路的分组、规则 |
| Shadowrocket | 小火箭配置：线路、规则；规则里的 `PROXY` 是首页点中的那条线路 |
| V2rayN、NekoBox、Hiddify、Karing 等读分享链接的客户端 | 线路的分享链接列表（base64） |
| 认不出来的客户端 | Clash 配置 |

也可以在地址里指定：`/s/<令牌>/mihomo`、`/shadowrocket`、`/raw`（base64 的链接列表）、`/uri`（明文的链接列表）；短链接用 `?format=`。“只给节点”的用户没有配置，他的页面上列出每条线路的链接和二维码。

面板不再为 Surge、sing-box 客户端生成配置，也不再有模板、分组预设、从节点库生成的订阅、转存的外部订阅和链式节点。

## 2. 线路

用户在客户端里看到的每一项是一条线路：直连某个入站，或者由入口机转到落地机。中转在入口机上完成，所以每条线路在客户端里都是入口机上的一个普通节点，落地机的地址和凭据不出现在任何配置里。每个用户在每条线路上有自己的凭据。

外部节点（别处给的订阅或节点链接）可以加给用户，排在线路后面。上游用节点名字夹带的“剩余流量”“到期时间”之类的条目不会进入线路列表。

## 3. 规则

一套规则是一份清单，一行一条：`类型,内容,动作`，动作是 `PROXY`（走用户选的线路）、`DIRECT`（直连）、`REJECT`（拒绝）。Clash 和小火箭的配置都由同一份清单生成，写法和可用的名单见面板「规则」页里的说明。监听、DNS、嗅探这些每种客户端内置一份，不在面板里编辑。

用户没有线路时（暂停、流量用尽、到期），配置里凡是 `PROXY` 的地方都是拒绝，不会变成直连。

## 4. 排查

1. 客户端里看不到新线路：先更新配置。小火箭默认不会自己更新，要在它的“设置 → 自动更新”里打开。
2. 小火箭里换线路不起作用：线路在首页点，不是在“代理分组”里。
3. 某条线路不通：用户页里看他在这条线路上的凭据是否“就绪”，再看入口机和落地机是否在线、配置是否已应用。
4. 链接打不开或提示停用：看用户的状态（暂停、流量用尽、到期、撤销）。
